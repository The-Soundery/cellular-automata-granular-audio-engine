Cellular Automata Granular Audio Engine - Creative Brief (V2)
Project Overview

Version 2 of this project is an evolution of the original Cellular Automata granular audio instrument. The fundamental philosophy remains unchanged:

The audio is NOT controlled by the Cellular Automata. The audio IS the Cellular Automata.

However, Version 1 revealed an important limitation. Whilst the audio was mathematically faithful to the simulation, it failed to preserve one of the most beautiful aspects of Cellular Automata - the emergence of spatial structures.

Version 2 introduces the concept of Topological Sonification.

The goal is no longer simply to sonify the state of the Cellular Automata, but to sonify:

State
Topology
Spatial relationships
Temporal relationships
Global relationships

The geometry of the simulation should become audible.

Core Design Philosophy

We are NOT building:

A granular synthesiser controlled by visuals
An audiovisual music visualiser
A sonification of RGB values
A collection of DSP effects mapped to Cellular Automata

We ARE building:

One Cellular Automata universe
One shared mathematical state
Two renderers:
Visual Renderer
Audio Renderer

Both renderers are simply different ways of observing the same underlying computational universe.

Every sonic event must be directly derived from properties that already exist within the Cellular Automata simulation.

No arbitrary audio systems should be introduced unless they correspond to a fundamental property of the simulation.

Visual Engine

The visual simulation should continue to use the existing Utomata Cellular Automata engine.

The Cellular Automata provides:

Cell positions
RGB values
Neighbour relationships
Temporal evolution
Global simulation state
Editable CA equations

The audio engine should observe and interpret these properties in real time.

V2 AUDIO PHILOSOPHY

Version 1 focused primarily on cell state and neighbour relationships.

Version 2 introduces a new principle:

Spatial topology is a fundamental property of Cellular Automata and should therefore be sonically meaningful.

The visual movement of structures should create corresponding sonic movement.

Examples:

Vertical structures should create spectral movement.
Horizontal structures should create sample movement.
Stable structures should create sustained textures.
Chaotic structures should create more intricate granular behaviour.
Colour evolution should create timbral evolution.

The listener should be able to hear the emergence of large-scale computational structures.

AUDIO ARCHITECTURE

The audio engine is divided into five layers.

Layer 1 - Spatial Topology

The X and Y axes of the Cellular Automata are now fundamental audio parameters.

X Axis
Sample Position

The horizontal axis determines where within the source audio the grain is extracted.

Examples:

Left side of the simulation = beginning of the source audio.
Right side of the simulation = end of the source audio.

Horizontal movement through the simulation becomes movement through the source material.

Y Axis
Frequency / Spectral Position

The vertical axis determines where within the frequency spectrum the grain exists.

Examples:

Bottom of the simulation = lower frequencies.
Top of the simulation = higher frequencies.

Vertical movement becomes spectral movement.

This creates a direct audiovisual relationship between:

Shape
Position
Movement
Sonic evolution

The topology of the simulation should now be audible.

Layer 2 - Timbral Space

RGB values no longer control sample position or frequency.

RGB values define the material properties of the grain.

The goal is NOT to implement traditional DSP effects.

Examples of what should NOT be implemented:

Reverb
Distortion
Filters
FM synthesis
Conventional effect chains

Instead, RGB exists within a continuous timbral space.

Current proposal:

R = Spectral Density

G = Spectral Complexity

B = Spectral Coherence

These properties determine how the existing information within a grain is organised.

Spectral Density

Produces timbral characteristics such as:

Dense
Focused
Tonal
Crystal-like
Solid

Density describes how tightly organised the grain's information is.

Spectral Complexity

Produces timbral characteristics such as:

Organic
Detailed
Intricate
Airy
Rich

Complexity describes how much detail exists within the grain.

Spectral Coherence

Produces timbral characteristics such as:

Smooth
Liquid
Stable
Fluid
Continuous

Coherence describes how smoothly the grain's information is organised.

Timbral Materials

The RGB values should not behave like three independent parameters.

Instead, they should define coordinates within a continuous timbral material space.

Examples:

255,0,0

↓

Dense and focused.


0,255,0

↓

Intricate and organic.


0,0,255

↓

Smooth and fluid.


120,180,220

↓

A unique material existing between all three properties.

The resulting timbre should emerge from the balance between these three properties rather than from the blending of independent audio effects.

The intention is for Cellular Automata colour gradients to naturally become timbral gradients.

Layer 3 - Spatial Relationships

Spatial relationships are derived from neighbouring cells.

Examples include:

Neighbour similarity
Neighbour variance
Neighbour energy

These determine:

Grain Length

Grain Overlap

Voice Sharing
Grain Length

Large coherent regions should naturally produce:

Longer grains
More sustained textures

Highly differentiated regions should naturally produce:

Shorter grains
More granular textures
Grain Overlap

Neighbour relationships determine how grains blur together.

Examples:

Stable regions:

Greater overlap
More continuous sonic textures

Chaotic regions:

Less overlap
Greater detail and motion
Voice Sharing

Large coherent regions should not consume excessive voices.

Voice allocation should represent:

Information density
Spatial coherence
Temporal behaviour

The system should efficiently represent large structures whilst preserving their sonic identity.

Layer 4 - Temporal Relationships

Temporal relationships are derived from previous cell states.

Examples include:

How long has the cell existed?

How rapidly is it changing?

How stable is it over time?

These determine:

Retrigger Rate

Voice Persistence

Information Density
Retrigger Rate

Rapidly evolving areas should naturally become more active.

Stable regions should become more sustained and less frequently retriggered.

Voice Persistence

Temporal stability should influence:

Sustained grains
Continuous textures
Grain persistence

The audio should faithfully represent the temporal evolution of the Cellular Automata.

Information Density

Information density should describe:

How much unique computational information exists within a particular region of the simulation?

Factors may include:

Spatial variance
Temporal variance
Energy distribution

Information density should inform voice allocation throughout the audio engine.

Layer 5 - Global Relationships

Global simulation properties determine:

Master Gain

Maximum Simultaneous Voices

Energy Distribution

Potential measurements include:

Total simulation energy
Total information density
Number of active regions
Master Gain

The audio engine should normalise itself against the total energy of the simulation.

The simulation should behave as though it contains a finite amount of sonic energy that is continuously redistributed as structures emerge and evolve.

Maximum Simultaneous Voices

Voice allocation should be dynamically managed according to:

Information density
Spatial relationships
Temporal relationships
Global energy distribution

Large structures should sound large and coherent without unnecessarily increasing CPU usage.

Source Audio

The user should be able to load:

WAV
MP3
AIFF

The source audio should continue to function as the raw material from which all grains are derived.

The Cellular Automata simulation continuously explores and redistributes this material across:

Sample position
Frequency position
Timbral material space
Spatial relationships
Temporal relationships
Implementation Requirements

Version 2 should continue to be implemented as a browser-based web application.

Suggested technologies:

Utomata
WebGL / Canvas
Web Audio API
AudioWorklet
JavaScript / TypeScript
Vite

The visual simulation should remain fully interactive and allow users to:

Move through variations of CA equations
Restart and reset simulations
Load source audio
Observe audiovisual evolution in real time
Final Creative Goal

The goal of Version 2 is to create an audiovisual instrument that allows users to listen to the topology of emergence.

The listener should be able to hear:

The geometry of the simulation.
The movement of computational structures.
The evolution of timbral materials.
The redistribution of sonic energy.
The emergence and collapse of patterns through time.

The beauty of the visuals should emerge from simple local relationships between cells.

The beauty of the sound should emerge from those exact same relationships.

Version 2 is not intended to sound like granular synthesis being processed with effects. Instead, it should feel like listening to the material properties and geometry of a living computational universe as it evolves in real time.
